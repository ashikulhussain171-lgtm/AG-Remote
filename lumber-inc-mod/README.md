# Lumber Inc 1.13.3 currency mod

Target: `com.lumber.inc` 1.13.3, `split_config.arm64_v8a.apk` → `lib/arm64-v8a/libil2cpp.so`
(sha256 `42bea638…c997`, Unity IL2CPP metadata v31). Other builds are refused by the patcher.

## What is patched (measured on this build)

| Method | RVA | File offset |
|---|---|---|
| `Lumber.CurrencyResourceSelfAmount.ValidateNumber(double, string)` | `0x31552C8` | `0x31512C8` |
| `Lumber.CurrencyResourceFromWorld.ValidateNumber(double, string)` | `0x31540E8` | `0x31500E8` |

Both helpers are the only place currency balances are written through: `ValidateCurrentAmount`
(on load, label `"amount"`), `DoAddAmount` (`"value"`, `"newAmount"`) and `DoRemoveAmount`
(`"value"`, `"prevAmount"`, `"newAmount"`). The replacement keeps the original non-finite → 0
rule, passes inputs (label `"value"`, literal slot pointer at `0x63221F0`) through unchanged,
and clamps every currency balance to ≥ `FLOOR` = 1e236 (224 nines × 10^12, as a double). That
covers all `CurrencyType_2025` values (Gold 10, Diamond 20, BizPoint 30, Reputation 40,
VillageCoin 50, Gear 60) and all legacy `Currency` values (Gold 1, Diamond 2, BizPoint 16,
Reputation 32, VillageCoin 64, event coins 128+). `TARGETS` can still restrict it to a type list.

The "NOT ENOUGH DIAMOND" popup (`NotEnoughDiamondPopup.OpenPopup`) is reached from spend-failed
handlers; the failing condition is `RuntimeResourceSpendable_Basic.RefreshIsSpendable`
(`0x3156294`): `IsSpendable = resource.Amount >= spendAmount` (`fcmp d8, d9; cset ge` at `0x3156480`).
`World.get_Diamond` etc. read the same resource amount, so one patch covers both paths.

## Rebuild

```
python3 patch_libil2cpp.py <orig libil2cpp.so> libil2cpp.so          # needs keystone-engine, capstone
python3 rebuild_apks.py Lumber.Inc_1.13.3.apks libil2cpp.so <outdir>  # writes *.unsigned.apk
zipalign -f -p 4 X.unsigned.apk X.aligned.apk && apksigner sign --ks <ks> --out X.apk X.aligned.apk  # both APKs, same key
```

`release/` holds the signed `.apks` as a two-volume 7z (GitHub 100 MB limit); the
`lumber-mod-release` workflow extracts it and publishes the GitHub release.

## Panther Mods menu build (runtime on/off)

The menu build keeps the **original** `libil2cpp.so` and patches code in memory only while a switch
is on, so with every switch off the game runs unmodified.

- `menu/src/com/panther/mod/ModMenu.java` — "P" bubble in its own TYPE_APPLICATION_PANEL window (above the Unity SurfaceView; drag / tap) with four switches;
  states saved in SharedPreferences `panther_mods` and re-applied once `libil2cpp.so` is mapped.
- `menu/src/com/panther/mod/MemPatcher.java` — finds the module base in `/proc/self/maps`
  (mapping with file offset 0), checks every site holds this build's original or patched bytes,
  writes through `libpanther.so`, rolls back on a failed write, reads back to confirm.
  (Android refuses app writes to `/proc/self/mem` — `FileNotFoundException` — so that path is not used.)
- `menu/jni/panther.c` → `lib/arm64-v8a/libpanther.so` in the arm64 split: freestanding (no libc,
  no NDK needed), `nativeWrite` = mprotect RWX → copy → dc cvau/ic ivau → mprotect R-X;
  `nativeRead` copies bytes out of the mapping.
- `menu/src/com/panther/mod/Patches.java` — generated by `gen_patches.py` from the real library.

| Switch | Sites (RVA) | Change |
|---|---|---|
| Unlimited Currency | `0x31552C8`, `0x31540E8` | ValidateNumber floor 1e236 (above) |
| Free Upgrades / Level Up | `0x3156484` | `cset w1, ge` → `mov w1, #1` in `RuntimeResourceSpendable_Basic.RefreshIsSpendable` |
| | `0x312C178` | `ConstructionResource.DoRemoveAmount` → `ret` |
| | `0x2EEFF8C` | `SupervisorV2.SupervisorCardResource.DoRemoveAmount` → `ret` |
| Max Level (1 tap) | `0x4183BB0` | `Upgradable<object>.Upgrade`: `cmp w22, w0` → `subs w22, w22, w0` |
| | `0x4183C34` | `add w8, w8, #1` → `sub w8, w8, w22` (index jumps to the provider's max) |
| | `0x4183C2C` | `mov w1, #1` → `mov w1, wzr`: `UpdateCachedLevels(isUpgrade: false)` rebuilds current/next from the new index (with `true` it promoted the cached old+1 level, so the jump only showed as +1) |
| No Ads | `0x2A8F79C` | `Mediation.get_AdFree` → true (rewarded video rewards without an ad, via `InterceptRv`) |
| | `0x355D994` | `Screw.Idle.AdsFreeManager.get_IsAdFree` → true |
| | `0x34C1E4C` | `Screw.Store.get_ShouldShowAds` → false (interstitial + banner gates) |

Hook: `com.unity3d.player.UnityPlayerActivity.onCreate` (in `classes13.dex`) calls
`ModMenu.start(this)` right after `setContentView`; the menu code ships as `classes15.dex`.

```
python3 gen_patches.py <orig libil2cpp.so> menu/src/com/panther/mod/Patches.java
javac --release 8 -cp android-23/android.jar -d classes menu/src/com/panther/mod/*.java
dalvik-exchange --dex --min-sdk-version=26 --output=panther.dex classes
# classes13.dex: apktool d (smali) -> add the invoke-static line -> apktool b
clang --target=aarch64-linux-android29 -O2 -fPIC -ffreestanding -fno-builtin -fno-stack-protector -nostdlib -shared \
      -fuse-ld=lld -Wl,-soname,libpanther.so -Wl,-z,max-page-size=16384 -Wl,--hash-style=both -o libpanther.so menu/jni/panther.c
python3 build_menu_apks.py Lumber.Inc_1.13.3.apks classes13_hooked.dex panther.dex libpanther.so <outdir>
# then zipalign -p 4 + apksigner both APKs with one key
```
